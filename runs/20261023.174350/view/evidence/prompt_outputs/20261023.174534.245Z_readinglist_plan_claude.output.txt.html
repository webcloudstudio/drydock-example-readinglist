# ARCHITECTURE: ReadingList

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | Modules, boundaries, and technical decisions for the ReadingList Flask web application. |
| Depends On | None |
| Provides | project tree, pytest -q |

## Questions

- None.

## Purpose

ReadingList is a single-reader web application. A reader adds a book with a title and author, views books in the order added, and removes books. Empty titles or authors are rejected with a clear error. The application ships automated tests and a POSIX `bin/test.sh`.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file is the decision of record.

| Technology | Where it applies |
|------------|------------------|
| Python | Implementation language; project tree and environment. |
| Flask | Web framework; application factory `app_server.create_app()`. |
| SQLite | Persistence through the generated `persistence` package. |
| pytest | Automated tests, run as `pytest -q`. |
| HTML/CSS | Server-rendered pages with minimal CSS, no client-side JavaScript. |

## Project Layout

| Path | Role |
|------|------|
| `pyproject.toml`, `uv.lock` | Dependency manifest (Flask, pytest) and committed lockfile. |
| `.venv` | Environment created by `uv venv`. |
| `app_server/__init__.py` | `create_app() -> Flask`. |
| `app_server/testing.py` | `web_client()` plain callable. |
| `app_server/routes/` | Flask blueprints: JSON routes (`books.py`) and page routes (`pages.py`). |
| `app_server/services/books.py` | Book service: `add_book`, `list_books`, `remove_book`, `validate_book_input`. |
| `app_server/templates/` | Jinja templates (base layout, reading list page). |
| `persistence/` | Generated by Drydock from `DATABASE.md`; never hand-written. |
| `tests/` | pytest suite with `conftest.py` exposing the `web_client` and `db_session` fixtures. |
| `bin/test.sh` | POSIX test runner. |

## Module Ownership

| Boundary | Owning module | Allowed low-level access |
|----------|---------------|--------------------------|
| Persistence | `persistence` (generated) | The only module that touches SQLite. |
| Book rules and orchestration | `app_server.services.books` | Calls `db.books.<verb>(...)` only. |
| HTTP routes | `app_server.routes` | Call the service; never the database. |
| Configuration | `app_server.__init__` | Resolves `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db`. |
| File stores / external services | None | Not used. |

## Layering

Routes call services; services call `db.<table>.<verb>(...)`. SQL, sessions, table names, and column names never cross the persistence boundary. Books are always returned ordered by id ascending, which is the order added.

## Technical Decisions

- Test runner command is `pytest -q` from the application root.
- Rejected input returns 400; removal of an unknown book returns 404 (see `DECISIONS.json`).
- Server-rendered forms provide the user interface; JSON routes share the same services.

| Field | Value |

| Depends On | FEATURE-AppShell.md, DATABASE.md |
| Provides | POST /books |
| Consumes | books.create, books.get |

## Questions

- None.

## Purpose

Let the reader add a book. A valid submission is stored and returned; the new book appears in later list reads.

## Trigger

A client sends `POST /books` with a JSON body.

## Sequence

1. The route parses the JSON body for `title` and `author`.
2. The service `app_server.services.books.add_book(db, title, author)` stores the book via `books.create`.
3. The route returns 201 with the stored book.

## Routes

| Route | Behavior |
|-------|----------|
| `POST /books` | JSON `{"title": ..., "author": ...}`. Returns 201 with JSON `{"id", "title", "author"}`. Validation of empty fields is owned by FEATURE-RejectEmptyFields.md. |

## Reads

`books.get` is used to return the stored row.

## Writes

`books.create` inserts one row per valid submission; ids ascend in insertion order.

## Database Interface

- `FEATURE-BOOK-001` — write: create a book - supplies: `title`, `author` - returns: `id`, `title`, `author`
- `FEATURE-BOOK-002` — read: retrieve a book by id - supplies: `id` - returns: `id`, `title`, `author`

## Tests

The build writes pytest tests under `tests/` covering a valid add, the 201 response fields, and a read-back of the stored row.

# FEATURE: Reject Empty Fields

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | Reject a submission whose title or author is empty with a clear error and store nothing. |
| Depends On | FEATURE-AddBook.md |
| Provides | validate_book_input |
| Consumes | POST /books |

## Questions

- None.

## Purpose

Guarantee the application never accepts an empty title or empty author. Rejection reports a clear, human-readable error naming the offending field.

## Trigger

A submission to `POST /books` (or the page form route) carries a missing, empty, or whitespace-only title or author.

## Sequence

1. The service calls `validate_book_input(title, author)` in `app_server.services.books` before any store call.
2. A value that is missing, not a string, or empty after stripping surrounding whitespace raises `ValueError` whose message names the field (`title` or `author`).
3. `POST /books` converts the error to status 400 with JSON `{"error": <message>}`.
4. Nothing is stored; the book list is unchanged.

## Routes

This feature adds no route of its own; it governs `POST /books` provided by FEATURE-AddBook.md.

## Reads

None.

## Writes

None. A rejected submission writes nothing.

## Database Interface

- None — persistence is owned by FEATURE-AddBook.md.

## Tests

The build writes pytest tests for empty title, empty author, both empty, missing keys, and whitespace-only values, asserting status 400 and that the list is unchanged.
