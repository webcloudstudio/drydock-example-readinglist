# FEATURE: Remove Book

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | Remove a book from the reading list so it never reappears in later reads. |
| Depends On | FEATURE-AddBook.md, FEATURE-ListBooks.md, DATABASE.md |
| Provides | DELETE /books/{book_id} |
| Consumes | books.delete, books.get, GET /books |

## Questions

- None.

## Purpose

A reader removes a book they no longer want on their list. Once removed, the book must be absent from every subsequent list read, and the remaining books keep the order in which they were added.

## Trigger

An HTTP `DELETE /books/{book_id}` request, where `book_id` is the integer id returned when the book was added.

## Sequence

1. The route parses `book_id` as an integer. A non-integer id does not match the route and is answered by the framework as an unknown resource (404).
2. The service looks the book up through `books.get`. If it does not exist, the route answers 404 with a JSON error body.
3. The service removes the book through `books.delete`.
4. The route answers 204 with an empty body.

## Routes

| Route | Method | Success | Failure |
|-------|--------|---------|---------|
| `/books/{book_id}` | DELETE | 204, empty body | 404 for an unknown id, including a repeat removal of the same id |

## Reads

- `books.get` — confirms the book exists before deletion.

## Writes

- `books.delete` — permanently removes the book row.

## Database Interface

- `FEATURE-BOOK-004` — write: remove a book - supplies: `id` - returns: `id`
- `FEATURE-BOOK-002` — read: get a book by id - supplies: `id` - returns: `id`

## Operational Behavior

- Removal never alters the ids or relative order of the remaining books.
- A removed book must not reappear in any later read, including after the application restarts.
- Removing an already removed id is a no-op on state and answers 404.

## Programmatic Acceptance

=== AC remove-book-deletes ===
Intent: Removing an added book answers 204 and the book is absent from the next list read.
Suite: scoped

import uuid
from app_server.testing import web_client

client = web_client()
title = "ac-remove-" + uuid.uuid4().hex
author = "ac-remove-author"
created = client.post("/books", json={"title": title, "author": author})
assert created.status_code == 201
book_id = created.get_json()["id"]
try:
    before = [b["id"] for b in client.get("/books").get_json()]
    assert book_id in before
    removed = client.delete(f"/books/{book_id}")
    assert removed.status_code == 204
    after = [b["id"] for b in client.get("/books").get_json()]
    assert book_id not in after
finally:
    client.delete(f"/books/{book_id}")
=== END AC remove-book-deletes ===

from app_server.testing import web_client

client = web_client()

# SCREEN: Reading List

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | Server-rendered page that shows the reading list in the order added, with an add form, error display, and per-book remove buttons. |
| Depends On | FEATURE-AddBook.md, FEATURE-RejectEmptyFields.md, FEATURE-ListBooks.md, FEATURE-RemoveBook.md, FEATURE-AppShell.md |
| Provides | GET /, POST /add, POST /remove/{book_id} |
| Consumes | GET /books, POST /books, DELETE /books/{book_id} |
| Route | / |
| Parent | — |
| Main Menu | Reading List (1) |
| Tab Order | — |

## Questions

- None.

## Purpose

The single page of the application. A reader sees their books in the order they were added, adds a book with a title and author, sees a clear error when either is empty, and removes books they no longer want.

## Layout

- Page heading: "Reading List".
- Add form with a `title` text input, an `author` text input, and an "Add" submit button, posting to `/add`.
- Error region directly above the form, rendered only when a submission was rejected. It states which field is missing.
- Ordered list of books, one entry per book showing title and author, in the order added (id ascending).
- Each entry carries a "Remove" button, a form posting to `/remove/{book_id}`.
- An empty list renders a short "No books yet" message instead of the list.

## Routes

| Route | Method | Behavior |
|-------|--------|----------|
| `/` | GET | Renders the page with all books in the order added; status 200. |
| `/add` | POST | Form fields `title` and `author`. Valid input stores the book through the book service and redirects 303 to `/`. Empty or whitespace-only title or author re-renders the page with status 400, a visible error message, and nothing stored. |
| `/remove/{book_id}` | POST | Removes the book through the book service and redirects 303 to `/`. An unknown id also redirects 303 to `/` without changing state. |

The screen calls the same service functions that back `POST /books`, `GET /books`, and `DELETE /books/{book_id}`, so browser and JSON behavior cannot diverge. No client-side JavaScript is used.

## Interactions

1. The reader fills in both fields and submits; the page reloads with the new book at the end of the list.
2. The reader submits with an empty title or author; the page reloads with an error message and the list unchanged. Entered values are preserved in the form.
3. The reader presses "Remove" on a book; the page reloads without that book.

## Database Interface

- None — persistence is owned by FEATURE-AddBook.md.

# FEATURE: Test Runner

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | Provide a POSIX-compatible bin/test.sh that runs the complete automated suite and exits zero only when every test passes. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-AppShell.md, FEATURE-AddBook.md, FEATURE-RejectEmptyFields.md, FEATURE-ListBooks.md, FEATURE-RemoveBook.md, SCREEN-ReadingList.md |
| Provides | bin/test.sh |
| Consumes | pytest -q |

## Questions

- None.

## Purpose

Give the reader and the build a single dependable command, `sh bin/test.sh`, run from the application root, that executes every automated test and reports success only when all of them pass. This is the terminal verification story: it runs after every implementation story, and its command, exit code, standard output, and standard error are preserved as evidence.

## Trigger

`sh bin/test.sh` from the application root, or `sh sources/full_test.sh`, which dispatches to it.

## Sequence

1. The script changes to the application root (the parent of `bin/`), independent of the caller's working directory.
2. It activates `.venv` when `.venv/bin/activate` exists; otherwise it uses the interpreter on `PATH`.
3. It runs `pytest -q`.
4. It exits with pytest's exit status, so zero means every test passed and any failure, error, or collection problem is non-zero.

## Interfaces

| Interface | Contract |
|-----------|----------|
| `bin/test.sh` | POSIX `sh` only: no bashisms, no arrays, no `[[ ]]`. Uses `.` rather than `source`. Does not mask pytest's exit status. |

## Coverage Expectations

The suite under `tests/` contains tests for adding a book, listing books in the order added, removing a book, and rejecting an empty title or author. Each behavior has at least one test.

## Reads

- `tests/` and `.venv` in the application root.

## Writes

- None beyond what pytest itself writes (caches).

## Database Interface

- None — persistence is owned by FEATURE-AddBook.md.

## Programmatic Acceptance
