Application Structure

The application uses a Flask factory in app_server.create_app. Web routes are registered by the application factory. Feature modules handle request workflows and call the generated persistence package for storage.

Module Ownership

BoundaryOwnerRule
Application factoryapp_serverCreates and configures the Flask application.
Web routesFeature modulesTranslate HTTP requests into feature operations.
PersistenceGenerated persistence packageOwns database connections, schema operations, and repository calls.
Configurationapp_serverResolves application settings and database configuration.
Templates and stylingInterface layerRenders the server-rendered reading-list screen.
External servicesNoneNo external services are required.

Technical Decisions

  • The primary page is served at /.
  • Book creation uses POST /books.
  • Book removal uses POST /books/<book_id>/delete.
  • Features access persistence only through generated repository operations.

Programmatic Acceptance

=== AC architecture-factory ===
Intent: The application exposes the selected Flask factory and testing client contracts.

from flask import Flask from app_server import create_app from app_server.testing import web_client

app = create_app() assert isinstance(app, Flask) client = web_client() assert client is not None === END AC architecture-factory ===

=== AC architecture-testing ===
Intent: The application factory can be created repeatedly for isolated automated tests.

from app_server import create_app

first = create_app() second = create_app() assert first is not second assert first.name == second.name === END AC architecture-testing ===
