# ARCHITECTURE: ReadingList

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | Modules, routes, boundaries, and technical decisions for the ReadingList web application. |
| Depends On | None |
| Provides | create_app |

## Questions

- None.

## Purpose

ReadingList is a small Flask web application that keeps an ordered list of books to read. A reader adds a book (title and author), views books in the order added, and removes a book. Empty titles or authors are rejected with a reason.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file remains the decision of record.

| Technology | Where it applies |
|------------|------------------|
| Python | Implementation language, project root, `.venv` environment, `pyproject.toml`, committed `uv.lock` |
| Flask | Web framework behind `app_server.create_app()` |
| SQLite | Persistence store behind the generated `persistence` package |
| pytest | Automated test runner, invoked as `pytest -q` from the application root |
| HTML/CSS | Server-rendered pages using Jinja templates |

## Modules

| Module | Responsibility |
|--------|----------------|
| `app_server/__init__.py` | `create_app() -> Flask` application factory; registers routes, templates, and error handlers |
| `app_server/testing.py` | `web_client()` returning a Flask test client with `TESTING` enabled |
| `app_server/templates/` | Jinja templates, including `base.html` |
| `persistence/` | Generated by Drydock from `DATABASE.md`; never written by hand |
| `tests/` | Project pytest suite; `conftest.py` exposes `web_client` and `db_session` fixtures |
| `bin/test.sh` | POSIX `sh` runner for the complete suite (owned by the verification story) |

## Module Ownership

| Boundary | Owning module | Allowed low-level access |
|----------|---------------|--------------------------|
| Persistence | `persistence/` (generated) | Only this package touches the SQLite driver |
| Configuration | `app_server/__init__.py` | Resolves `DATABASE_URL`, then `DATABASE_PATH`, then `data/app.db` |
| File store | None | Not used |
| External services | None | Not used |

Routes call `db.books.<verb>(...)` on the object returned by `open_database(...)`. SQL, table names, and column names never appear in route code.

## Routes

| Route | Owner | Purpose |
|-------|-------|---------|
| `GET /` | SCREEN-ReadingList.md | Reading list page |
| `GET /books` | FEATURE-ListBooks.md | JSON array of books in the order added |
| `POST /books` | FEATURE-AddBook.md | Add a book; validation owned by the rejection features |
| `POST /books/{id}/delete` | FEATURE-RemoveBook.md | Remove a book |

## Technical Decisions

- Success responses to form posts are `303` redirects to `/`; rejections are `400`; an unknown book id is `404`.
- Order added is the ascending integer primary key `id`; no position column exists.
- A rejection always carries a non-empty reason.

# FEATURE: Add Book

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | A reader adds a book with a title and an author and it is stored. |
| Depends On | ARCHITECTURE.md, DATABASE.md, UI-GENERAL.md |
| Provides | POST /books |
| Consumes | books.create |

## Questions

- None.

## Purpose

Let a reader add a book to the end of the reading list.

## Trigger

A form post to `POST /books` with fields `title` and `author`.

## Sequence

1. Read `title` and `author` from the form, trimmed of surrounding whitespace.
2. Validation of empty values is owned by FEATURE-RejectEmptyTitle.md and FEATURE-RejectEmptyAuthor.md; this feature handles valid submissions.
3. Store the book through `db.books.create(title=..., author=...)`.
4. Answer `303` redirecting to `/`.

## Reads

- None.

## Writes

- One new book via `books.create`.

## Database Interface

- `FEATURE-BOOKS-001` — write: create a book - supplies: `title`, `author` - returns: `id`, `title`, `author`

# FEATURE: List Books

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | The application presents stored books in the order they were added. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-AddBook.md |
| Provides | GET /books |
| Consumes | books.list |

## Questions

- None.

## Purpose

Let a reader (and the reading list page) view every book in the order added.

## Trigger

A `GET /books` request.

## Sequence

1. Call `db.books.list()`, which returns rows by ascending `id`.
2. Respond `200` with a JSON array of objects carrying `id`, `title`, and `author`, in that same order.
3. An empty store yields an empty array.

## Reads

- All books via `books.list`.

## Writes

- None.

## Database Interface

- `FEATURE-BOOKS-002` — read: list books in the order added - returns: `id`, `title`, `author`

## Programmatic Acceptance

# FEATURE: Remove Book

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | A reader removes a book so it no longer appears in the list. |
| Depends On | ARCHITECTURE.md, DATABASE.md, FEATURE-AddBook.md |
| Provides | POST /books/{id}/delete |
| Consumes | books.get, books.delete |

## Questions

- None.

## Purpose

Let a reader remove a book from the reading list.

## Trigger

A form post to `POST /books/{id}/delete`.

## Sequence

1. Look up the book with `db.books.get(id=...)`.
2. If it does not exist, answer `404` and change nothing.
3. Otherwise delete it with `db.books.delete(id=...)` and answer `303` redirecting to `/`.
4. Remaining books keep their relative order.

## Reads

- One book via `books.get`.

## Writes

- One deletion via `books.delete`.

## Database Interface

- `FEATURE-BOOKS-003` — read: get a book by id - supplies: `id` - returns: `id`, `title`, `author`
- `FEATURE-BOOKS-004` — write: delete a book - supplies: `id` - returns: `id`

## Programmatic Acceptance

=== AC remove-book-omitted-on-next-read ===
Intent: A removed book is answered with 303 and is absent on the next read.
Suite: scoped

from app_server.testing import web_client

client = web_client()
marker = "ac-remove-gone"
title = marker + " title"

def cleanup():
    for row in client.get("/books").get_json():
        if marker in row["title"]:
            client.post(f"/books/{row['id']}/delete")

cleanup()
try:
    assert client.post("/books", data={"title": title, "author": marker + " author"}).status_code == 303
    ours = [row for row in client.get("/books").get_json() if row["title"] == title]
    assert len(ours) == 1
    book_id = ours[0]["id"]
    response = client.post(f"/books/{book_id}/delete")
    assert response.status_code == 303
    after = [row["id"] for row in client.get("/books").get_json()]
    assert book_id not in after
finally:
    cleanup()
=== END AC remove-book-omitted-on-next-read ===
