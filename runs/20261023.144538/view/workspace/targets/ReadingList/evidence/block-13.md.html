SUMMARY: Added tests/test_validation.py, which covers the FEATURE-ValidationTests spec. It runs eight rejected submissions (empty, whitespace-only, and missing title; empty, whitespace-only, and missing author) through POST /books. Each test reads its outcome back through the public interface (the HTTP status, the parsed JSON body, and GET /books). The tests check the status code, a non-empty error, the named field, that the stored list is unchanged after a rejection, and that a browser-style rejection returns 400 with a non-empty page.

Choices I made:

  • Each test gets its own SQLite store, provisioned from schema.sql, following the sibling reject-empty modules. The web_client fixture reads DATABASE_URL at creation, so it uses that store and never touches data/app.db.
  • The "stored list unchanged" check seeds one book first, so a rejection that wrongly stored a row would be caught.
  • Assertions check status, presence of a reason, and field name, never the reason's wording, per the spec's guardrail.
