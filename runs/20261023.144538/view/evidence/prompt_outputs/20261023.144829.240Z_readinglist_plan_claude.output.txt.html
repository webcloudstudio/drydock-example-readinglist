# FEATURE: Reject Empty Title

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | A book submission whose title is empty is rejected with a reported reason and nothing is stored. |
| Depends On | FEATURE-AddBook.md, UI-GENERAL.md |
| Provides | None |
| Consumes | POST /books |

## Questions

- None.

## Purpose

The reader must never be able to add a book without a title. The submission is rejected and the reader is told why.

## Trigger

A reader submits `POST /books` where the `title` form field is missing, empty, or whitespace-only.

## Sequence

1. `POST /books` receives form fields `title` and `author`.
2. The title is trimmed. If the trimmed title is empty, validation fails. Title is checked before author, so when both are empty the rejection names `title`.
3. The route answers status 400 and stores nothing.
4. If the request carries `Accept: application/json`, the body is JSON with `error` (a non-empty reason string) and `field` equal to `title`.
5. Otherwise the page is re-rendered in the shared layout's error region with the reason shown, still with status 400.

## Routes

| Route | Behavior |
|-------|----------|
| `POST /books` | Extended by this feature with title validation; valid submissions remain owned by FEATURE-AddBook.md |

## Reads

None.

## Writes

None. A rejected submission writes nothing.

## Database Interface

- None — persistence is owned by FEATURE-AddBook.md.

from app_server.testing import web_client
from persistence.testing import committed_session

marker = "RejTitleEmptyAuthor01"


def purge():
    with committed_session() as db:
        for row in db.books.list():
            if row.author == marker:
                db.books.delete(id=row.id)


def stored():
    with committed_session() as db:
        return [row for row in db.books.list() if row.author == marker]


client = web_client()
purge()

    response = client.post(

        data={"title": "", "author": marker},
        headers={"Accept": "application/json"},

    assert body["error"].strip()
    assert body["field"] == "title"
    assert len(stored()) == 0
finally:

# SCREEN: Reading List

| Field | Value |
|-------|-------|
| Version | 20261023 V1 |
| Description | The single page where a reader adds books, sees them in the order added, sees rejection reasons, and removes books. |
| Depends On | FEATURE-ListBooks.md, FEATURE-RemoveBook.md, FEATURE-RejectEmptyTitle.md, FEATURE-RejectEmptyAuthor.md, UI-GENERAL.md |
| Provides | GET / |
| Consumes | GET /books, POST /books, POST /books/{id}/delete |
| Route | / |

## Questions

- None.

## Purpose

One page for the reader to track what they intend to read, in the order they added it.

## Layout

Rendered inside the shared base layout from `UI-GENERAL.md`:

1. Error region: shows the rejection reason when a submission was rejected; empty otherwise.
2. Add form: text inputs `title` and `author`, and a submit button, posting to `POST /books`.
3. Book list: an ordered list of books in insertion order. Each entry shows title and author and a remove form posting to `POST /books/{id}/delete`.
4. When no books exist the list area shows an empty-state message.

## Interactions

| Interaction | Route | Result |
|-------------|-------|--------|
| Open the page | `GET /` | Page lists every stored book in the order added |
| Submit the add form | `POST /books` | Valid: 303 redirect back to `/`. Rejected: 400 and the page re-rendered with the reason |
| Press remove on a book | `POST /books/{id}/delete` | 303 redirect back to `/`; the book is gone on the next read |
| Read the list as data | `GET /books` | JSON array of `id`, `title`, `author` in insertion order |

## Database Interface

- None — persistence is owned by FEATURE-AddBook.md.
