## Project Layout

- `pyproject.toml` with committed `uv.lock`; the environment is `.venv`, created by `uv venv`.
- `app_server/__init__.py` exposes `create_app() -> Flask`.
- `app_server/testing.py` exposes `web_client()`, which returns a Flask test client with `TESTING` enabled.
- `bin/test.sh` at the application root, written by the terminal story.

- Python: implementation language, governed by `python.md`.

- SQLite: local persistence through the generated `persistence` package, governed by `sqlite.md`.
- pytest: test runner for the automated suite.

# FEATURE: Add Book

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Accept a title and author, store the book, and reject an empty title or author. |
| Depends On  | ARCHITECTURE.md, DATABASE.md |
| Provides    | POST /books |
| Consumes    | books.create |

## Questions

- None.

## Purpose

A reader adds a book with a title and an author. An empty title or author is rejected with a clear error.

## Route

`POST /books` accepts a JSON body with `title` and `author`.

- A valid submission is stored through `books.create` and returns status 201 with the stored book as JSON: `id`, `title`, `author`.
- An empty or whitespace-only `title` returns status 400 with JSON `{"field": "title"}`.
- An empty or whitespace-only `author` returns status 400 with JSON `{"field": "author"}`.
- A rejected submission is not stored.

## Database Interface

- `FEATURE-BOOKS-001` — write: create a book - supplies: `title`, `author` - returns: `id`, `title`, `author`

## Programmatic Acceptance

=== AC add-book-stores-valid ===
Intent: A valid submission returns 201 with the stored book's title and author.

from app_server.testing import web_client

client = web_client()
response = client.post("/books", json={"title": title, "author": author})
assert response.status_code == 201

assert body["title"] == title
assert body["author"] == author
assert isinstance(body["id"], int)
=== END AC add-book-stores-valid ===

## Purpose

A reader views the books in the order they were added.

## Route

`GET /books` returns status 200 with a JSON array of books, each with `id`, `title`, and `author`. The array is ordered by ascending `id`, which is insertion order.

## Database Interface

- `FEATURE-BOOKS-002` — read: list books in insertion order - supplies: none - returns: `id`, `title`, `author`

## Programmatic Acceptance

=== AC list-books-returns-ok ===

from app_server.testing import web_client

client = web_client()

assert response.status_code == 200

=== END AC list-books-returns-ok ===

=== AC list-books-insertion-order ===
Intent: Books added in sequence are listed in the order they were added.

import uuid
from app_server.testing import web_client

author = uuid.uuid4().hex
first = uuid.uuid4().hex
second = uuid.uuid4().hex
third = uuid.uuid4().hex
client = web_client()
for title in (first, second, third):
    added = client.post("/books", json={"title": title, "author": author})
    assert added.status_code == 201
listing = client.get("/books")
assert listing.status_code == 200
titles = [book["title"] for book in listing.get_json() if book["title"] in (first, second, third)]
assert titles == [first, second, third]
=== END AC list-books-insertion-order ===

## User Acceptance

- None.

## Guardrails

- Never present books in an order other than the order they were added.

# FEATURE: Remove Book

| Field       | Value |
|-------------|-------|
| Version     | 20261014 V1 |
| Description | Remove a book so it is omitted from the next read; report a missing id without altering the list. |
| Depends On  | ARCHITECTURE.md, DATABASE.md, FEATURE-AddBook.md, FEATURE-ListBooks.md |
| Provides    | DELETE /books/{id} |
| Consumes    | books.get, books.delete |

## Questions

- None.

## Purpose

A reader removes a book from the list.

## Route

`DELETE /books/{id}`

- A stored id is removed through `books.delete` and returns status 204.
- An id that is not in the list returns status 404 and leaves the list unchanged.
- A removed book is absent from the next `GET /books`.

## Database Interface

- `FEATURE-BOOKS-003` — read: retrieve a book by id - supplies: `id` - returns: `id`, `title`, `author`
- `FEATURE-BOOKS-004` — write: delete a book by id - supplies: `id` - returns: `id`

## Programmatic Acceptance

=== AC remove-book-deletes ===
Intent: A removed book returns status 204 and is absent from the next list read.

import uuid
from app_server.testing import web_client

author = uuid.uuid4().hex
client = web_client()
added = client.post("/books", json={"title": uuid.uuid4().hex, "author": author})
assert added.status_code == 201
book_id = added.get_json()["id"]
deleted = client.delete(f"/books/{book_id}")
assert deleted.status_code == 204
listing = client.get("/books")
assert listing.status_code == 200
assert book_id not in [book["id"] for book in listing.get_json()]
=== END AC remove-book-deletes ===

=== AC remove-book-missing-id ===
Intent: Removing an id that is not in the list returns 404 and leaves the list unchanged.

import uuid
from app_server.testing import web_client

author = uuid.uuid4().hex
client = web_client()
added = client.post("/books", json={"title": uuid.uuid4().hex, "author": author})
assert added.status_code == 201
book_id = added.get_json()["id"]
assert client.delete(f"/books/{book_id}").status_code == 204
before = [book["id"] for book in client.get("/books").get_json()]
repeated = client.delete(f"/books/{book_id}")
assert repeated.status_code == 404
after = [book["id"] for book in client.get("/books").get_json()]
assert after == before
=== END AC remove-book-missing-id ===

## User Acceptance

- None.

## Guardrails

- Removing a missing id must not alter the list.
